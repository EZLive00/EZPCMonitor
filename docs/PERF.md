# 资源占用记录

这个项目的卖点是「轻」，所以每加一个功能、每改一次热路径，都要跑一遍
`./scripts/measure.sh`，把数字和上一行比。**看 delta，不看绝对值。**

## 怎么量

```bash
./scripts/measure.sh                          # 构建 + 测量，追加一行
./scripts/measure.sh --no-build --note "..."  # 用现有产物
```

脚本自己会把环境固定住：Release 构建、采集 1 秒（CPU 另测一档 5 秒）、悬浮窗卡片形态、
主面板背景为系统材质、主题跟随系统、历史记录关闭。跑之前备份 `settings.json` 和
UserDefaults，跑完原样还回去。

量图片背景那一档要显式指定，否则用户上次挑的照片会跟着进测量，两张表就没法比：

```bash
./scripts/measure.sh --no-build --note "图片背景" \
  --backdrop '{"kind":"image","image":"backdrop.jpg","opacity":0.94}'
```

## 口径

| 列 | 怎么来的 |
|---|---|
| `.app` | `du -sk` ÷ 1024，磁盘占用（含 `smartctl` 705 KB）。不用 `du -sm`：取整会把 5.9 报成 6、6.2 报成 7，一个 +0.3 MB 的改动看起来像 +1 MB |
| 二进制 | `stat` 取主可执行文件大小 |
| 悬浮窗 footprint | `footprint -p`，**不含** dyld 共享缓存，横向比较看这个 |
| 悬浮窗 RSS | 内核 `sysinfo` 报的口径，含共享缓存，比 footprint 大 |
| 主面板 footprint | 打开主面板 8 秒后 |
| CPU 1s / 5s | 采集频率 1 秒 / 5 秒下的常驻 CPU（单核百分比，5 次采样取中位数） |

CPU 走 `scripts/probe.swift` 而不是 `top` / `ps`：那两个要 `task_for_pid` 权限，在受限
环境里直接 `operation not permitted`。probe 复用内核自己的全进程表，和界面上显示的
数字同源。

## 噪声

同一份代码连测两次，数字会差：内存 ±1~2 MB，CPU ±0.5%。所以**改动小于 2 MB 或 1%
的差异没有意义**，别拿它当"优化成功"的证据。

结论：从基线到现在，磁盘 +0.6 MB，默认路径的内存没动。两笔额外开销都是「用户主动
要求才付」的：换成自定义图片背景 +4 MB，开着报告预览窗口 +19 MB（关掉就还回去）。

**CPU 这一列要看趋势，别抠单次。** 内存三列（footprint / RSS）重复测量的偏差只有
1~2 MB，CPU 能差出一倍：同一份产物在屏幕唤醒、桌面上有动画的情况下量到过 5.9% ~ 8.2%。
原因在毛玻璃——`.behindWindow` 每帧都要重算窗口背后的模糊，桌面内容一变（视频、滚动、
正在打字的窗口）成本就上去了。所以 CPU 只能横向比同一次会话里的两行，跨天比没意义。

**读数会飘，量之前先清场。** 同一份产物连量两遍，RSS 差 2 MB 是常态；有一次直接量出
悬浮窗 75 MB（历史一直 40 上下），再量一遍又回到 42——多半是上一轮 GUI 测试留下的实例
还在跑，`measure.sh` 抓到了另一个进程。所以：

- 量之前 `pkill -f 'EZPcMonitor.app/Contents/MacOS'`，确认没有别的实例。
- 单次异常值不要直接记进表里，重测一次；两次都对不上再查原因。
- 屏幕锁着的时候窗口服务不做合成，RSS 会明显偏低（同一份产物 41 vs 75 MB 那种量级
  的差别就是这么来的），所以测量时屏幕要保持唤醒。

## 图片背景的尺寸账

第一版把用户选的原图按 1400px 存下来，磨砂交给合成时的 `.withinWindow` 材质，
主面板 48 MB。逐项拆开量，结论和直觉相反：

| 配置 | 主面板 footprint |
|---|---|
| 系统材质（无图） | 31 MB |
| 1400px 原图 + `.withinWindow` 材质 | 48 MB |
| 1400px 预磨砂，去掉材质 | 47 MB |
| 400px 预磨砂，去掉材质 | 31 MB |
| 720px 预磨砂 + 材质 | 36 MB |

两层结论：

1. **那层材质只占 1 MB**，大头是图本身——开销基本正比于像素数，和磨不磨无关。
2. **磨过的图不需要大**。模糊之后 15px 以上没有细节，1400px 和 720px 显示出来是
   同一片渐变（实测平均亮度 77 / 76，标准差 0.056 / 0.027，后者只是更平）。

所以最终落盘 720px、半径 0.02×尺寸。材质留在图片上面不动——去掉试过，照片艳得
卡片都看不见，单靠纱补不回来：纱只能整体压黑，压不出那种去饱和的灰。


## 各窗口的占用

同一份产物，每次只开一个窗口量（`footprint -p <pid>`，开窗后 7 秒）：

| 状态 | footprint | 相对只挂悬浮窗 |
|---|---|---|
| 只有悬浮窗 | 18 MB | — |
| 打开主面板 | 32 MB | +14 MB（此时悬浮窗被收起） |
| 打开历史窗口 | 31 MB | +13 MB |
| 打开设置窗口 | 33 MB | +15 MB |
| 报告预览窗口 | +19 MB | 在历史窗口之上再叠 |

窗口都是关掉就整个放掉（`NSHostingView` 里的表格、进度条不常驻），所以这几个数是
「开着的时候多付多少」，不是常驻开销。
